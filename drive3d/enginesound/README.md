# リアルタイム・エンジンサウンド（物理モデル）v31

高速運転シミュレーター（`drive3d/index.html`）のエンジン音を、「音の波形を作る」方式から「音が生まれる仕組みを計算する」方式に作り替えた。
気筒の中の圧力・温度を毎サンプル解き、排気管・吸気管の中を圧力波が往復する様子を波動管（デジタル導波管）で計算して、排気の出口と吸気口から出る音を作る。
単純なピッチ変更や録音のループは使わない（ループする素材が無いので、音切れ・継ぎ目も原理的に出ない）。

## 1. 外部ツールの調査と選定

| ツール | ライセンス | 結論 | 使い方 |
|---|---|---|---|
| **Engine Simulator**（ange-yaghi/engine-sim） | MIT（Copyright 2022 AngeTheGreat。`LICENSE` で確認）| 設計の参考 + 比較の基準音 | 構成（気筒内圧力 → 排気の流れ → 遅延 → インパルス応答 → レベラー）を読み、同じ発想を JS の波動管で書き直した（コードは流用していない）。さらに C++ 本体を GUI なしの CLI としてビルドし、9 機種・7 条件の基準音を作って比較した |
| **FMOD** | 独自の EULA（小規模開発者向けの無料枠あり。帰属表示が必要。ソースの再配布は不可）| 不採用 | サンプルの再生・ミックス用のミドルウェア（エンジン音を「合成」するものではない）。単一 HTML のゲームに組み込めず、規約も合わない |
| **FFmpeg** | LGPL / GPL（同梱せず、開発用の外部コマンドとして使う）| 解析ツール | `ebur128` で聴感上の音量（LUFS）を測定。録音の形式変換・リサンプル（`-ac 1 -ar 48000`）|
| numpy / scipy / matplotlib / soundfile | BSD 系 | 解析ツール | 次数追跡・スペクトログラム・クリック/音切れ/ループの自動検査 |

また、基準音の WAV（約 115MB）と Engine Simulator のコードはリポジトリに入れていない（再現手順は「7. 基準音の作り方」）。

## 2. 仕組み

```
 クランク角 θ ─┬─ 気筒 k（点火順・バンクごとの着火角）
               │    圧縮 → 点火（ヴィーベ燃焼・進角・ばらつき）→ 膨張 → 排気バルブが開く（ブローダウン）→ 排気行程 → 吸気 → オーバーラップ（掃気）
               │    p, T, m を第一法則で毎サンプル積分。バルブの流れは管の側の圧力（反射波）と連立して解く
               ├─ 排気: プライマリー（長さの差）→ 集合部（4-1 / 4-2-1）→ バンク管 → Y 合流 / X・H パイプ → 触媒 → タービン → マフラー（拡張室）→ テールパイプ → 開口端（反射 + 放射 = 体積流量の微分）
               ├─ 吸気: 吸気口 ← 吸気管 ← スロットル（バタフライ弁。開度で反射が変わる）← プレナム ← ランナー ← 吸気バルブ。マニホールド圧は流量の収支から決まる
               └─ 燃焼の振動（ブロックを伝わる音）・排気口のジェット乱流・排気管内の爆発（バックファイア）
```

- コア: `src/engsim.js`（`EngSim`。Node でも動く単体モジュール）
- ゲームとの接続: `src/engsim_game.js`（`HW.PX`: 車のスペック・部品 → コアの設定、毎ブロックの制御量、レベラー、CPU の保護）
- `EngineSynth.render` への差し込み: `src/patch_rl_zphys.py`（物理モデルが使えない音源 — 測った表を持つディーゼル・軽量版・ハイブリッドの EV 走行 — は従来の合成のまま）
- 部品 → 排気・吸気の構造: `rl_sound.js` の `c.rl.snd.px`

### 対応する気筒配列（点火順・バンクのパターン）

I3 / I4 / 水平対向 4 / I5 / I6 / 水平対向 6 / V6（等間隔 60°）/ V6（不等間隔 90°: 150°・90° 交互）/ V8 クロスプレーン（1-8-7-2-6-5-4-3: バンクごとに不等間隔）/ V8 フラットプレーン / V10 / V12 / V14〜V20 / ロータリー（4 サイクル相当）。
カタログの 369 種の音源（`HW.SNDREQ`）と手書きの 40 種ほどのプロファイルが、気筒数・形式から自動で選ばれる。

### 制御量との接続（毎ブロック）

| ゲーム側 | 物理モデルでの役割 |
|---|---|
| 回転数 | クランク角の進み、ブローダウンの時間幅、管の共鳴との位置関係、吸気の流量 |
| スロットル開度 | バタフライ弁の開口面積 → マニホールド圧（アイドル約 40kPa、全開約 97kPa、エンジンブレーキ約 12kPa）→ 吸入空気量 → 燃焼圧力 → 排気パルスの強さ。吸気口に届く音（スロットルの反射）|
| 過給圧（ターボ・スーパーチャージャー）| スロットル上流の圧力 → 吸気量・燃焼圧力が増える。ターボはタービンが排気管に入り（抵抗 = 軸の回転 × ウエストゲートの開き）、パルスをならして高域を落とす |
| 負荷 | マニホールド圧から計算されるので、「負荷」の数値を音量にかけているわけではない |
| 燃料カット（エンジンブレーキ）| 燃焼なし。ポンピングだけの弱い排気 |
| アンチラグ | 点火を大きくリタード（−44°）・スロットルを少し開けて、排気弁が開く時の圧力と温度が上がり、不規則に爆ぜる |
| ポップ・バックファイア・リミッター・フラットシフト | 排気管の集合部への圧力の爆発（体積流量の注入）として入る。管の構造によって音色が変わる |
| ブローオフ・ウエストゲート・タービンの笛・スーパーチャージャーの唸り | 従来の発音（EngineSynth の過給機の音）を使い、制御量は同じ過給状態に接続 |

### 部品・チューニング → 構造

`c.adv`（ボア・ストローク・圧縮比・カム作用角・点火時期）→ 気筒の幾何とバルブタイミング。
`c.rl.snd.px`（触媒のセル数 → 抵抗、ヘッダー → プライマリーの長さ・4-2-1、センターパイプ径、マフラーの抜けのよさ → 拡張室の数・面積比・吸音、ITB・プレナム → 吸気）。

## 3. 品質条件への対応

| 条件 | 対応 | 確認 |
|---|---|---|
| 1. 単純なピッチ変更にしない | 回転で変わるのは周波数だけでなく、排気管・吸気管の共鳴との位置関係、ブローダウンの形、燃焼圧力 | スペクトログラムで、次数の線が管の共鳴帯域を通るたびに明るくなる |
| 2. 気筒数・点火順序・燃焼周期・排気脈動 | 点火順の着火角・バンク・集合のしかたを配列ごとに持ち、気筒の熱力学と波動管で計算 | 全 11 配列で、発火次数（気筒数/2）とその倍音が支配的。不等間隔 V6 は 1.5 次系列。ヘッダー・集合で脈動が変わる |
| 3. RPM・スロットル・負荷・過給圧 | 上の表 | 条件ごとの検査（部品・条件の効き方）|
| 4. 音切れ・不自然なループ | 録音・波形テーブルを使わない生成。遅延の変更は 0.0015 サンプル/サンプル以下で動かす（クリック防止）。NaN は検出して作り直す | 24 本のレンダリングでスパイク 0・音切れ 0・ブロック境界の不連続なし・掃引の自己相関 0.02〜0.07 |
| 5. 実車録音との比較 | 比較・当てはめのツール（`cmp_ref.py`, `fit_real.py`）。録音は著作物のためリポジトリに入れない | 基準（Engine Simulator）との比較結果は `reports/` |
| 6. ビルド・実行・結果の報告 | ゲームをビルドし、ヘッドレス Chromium で実行 | `reports/test_report.md` |

## 5. 実車の録音に合わせる

録音の一定回転の区間（例: 3000rpm 全開）を使って、排気系の構造パラメータを自動で探す。

```bash
ffmpeg -i real.m4a -ac 1 -ar 48000 real.wav
python3 fit_real.py --wav real.wav --rpm 3000 --arch i6 --n 6 --disp 3.0 --redline 7000 --band 60 4000
```

出力された `kJet`・触媒の抵抗・マフラーの構造・テールの長さを、車ごとの設定（`rl_sound.js` の `px`）に入れる。
`cmp_ref.py` は同じ回転・スロットルの 2 つの音（録音と合成）について、1/3 オクターブ帯の形と次数の構成を比べる。

## 6. 既知の制約

- 実車の録音は入手できず（著作物のため同梱もできない）、音色の調整は ①実測値の範囲に入るかの検査（気筒サイクル）②Engine Simulator の同条件の音との比較 ③物理的な妥当性の検査 に基づく。録音が手元にあれば `fit_real.py` で合わせられる
- Engine Simulator の基準音は、パルスを約 1.9kHz で低域通過してから既定のインパルス応答を畳み込むので、1kHz より上は基準より本モデルのほうが明るい（直接の一致は目標にしていない）
- ディーゼル（測った表を持つ音源）・ジェット・電動機・ハイブリッドの EV 走行は従来の合成のまま
- スマートフォン（軽量版）は従来の合成（CPU 負荷のため）。デスクトップでは物理モデルが従来の合成に加えて約 7〜15% の CPU（1 コアに対する実時間比。V8 で約 10%、V16 で約 15%）を使う。1 ブロックの計算が再生時間の 75% を超える状態が続くと、自動で従来の音に戻る
- 切り替え: `localStorage.setItem('hw.px','0')` または URL に `?px=0`（従来の音）

## 7. 基準音の作り方（Engine Simulator を GUI なしでビルド）

Engine Simulator 本体（C++）をクローンし、サブモジュール（piranha, simple-2d-constraint-solver, csv-io）を取得して、
GUI・Delta Studio に依存しない CLI（`es_render`）を別のディレクトリでビルドした。上流のコードは変更していない（MSVC 専用の部分は別のコピーに当てたパッチで対応）。
2JZ（I6）・Honda B18C5（I4）・60° V6 / 偶数点火 V6 / 奇数点火 V6・GM LS（クロスプレーン V8）・フェラーリ F136（フラットプレーン V8）・レクサス LFA（V10）・フェラーリ 412 T2（V12）の 9 機種を、
アイドル・3000rpm 全開・0.8×レッドライン全開・全開の掃引・3000rpm 25%・減速（燃料カットあり／なし）で出力した。
